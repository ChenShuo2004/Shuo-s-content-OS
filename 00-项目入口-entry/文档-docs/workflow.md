# Workflow / 工作流说明

内容 OS 的循环不是“多发内容”，而是“让每次发布都变成一次可结算的判断”。

```text
产品本体 -> 市场竞品 -> 平台策略 -> 草稿 -> 盲预测 -> 发布 -> T+N 复盘 -> 更新 rubric
```

## 1. 产品本体

位置：`01-产品本体-product-core/`

先确认这篇内容服务什么产品、用户问题和卖点。否则内容会被热点牵着走。

## 2. 市场竞品

位置：`02-市场与竞品-market-research/`

看同类产品、同类账号、平台语境和用户已有认知。

## 3. 平台策略

位置：`03-内容与销售-content-sales/<平台>/`

每个平台有自己的定位、发布清单、复盘数据、策略素材和资产索引。

## 4. 草稿

位置：`04-创作流水线-creation-pipeline/草稿-scripts/`

用 CLI 创建：

```bash
python "06-系统引擎-system-engine/工具-tools/content_os.py" new-script . "标题"
```

## 5. 盲预测

位置：`05-校准与复盘-calibration-retro/评分预测系统-scoring-prediction/预测日志-predictions/`

预测必须在看到数据前写。写完不要改预测段。

## 6. 发布登记

发布后把平台和 URL 追加到预测日志里，同时进入待复盘队列。

## 7. T+N 复盘

复盘需要写实际数据、预测偏差、被验证的判断和被推翻的判断。

## 8. 更新 rubric

单篇内容只写 memo。多个样本重复验证后，再更新正式 rubric。
